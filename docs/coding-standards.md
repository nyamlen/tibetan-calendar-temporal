# Coding standards

Every rule this project holds, and **what fails when you break it**.

That last part is the reason this file exists separately from the others.
[CLAUDE.md](../CLAUDE.md) states each rule together with the failure that produced it, which is what makes the rules persuasive; [CONTRIBUTING.md](../CONTRIBUTING.md) is the on-ramp.
Neither says which rules a machine will catch and which depend on somebody noticing.
This one does, and the honest answer differs by rule.

Read the **Enforced by** column first.
A rule with a command beside it will stop a push. A rule marked **review** will not — those are the ones to hold in your head, and the ones worth automating next.

## Runtime and language

| Rule | Enforced by | Why |
|---|---|---|
| `Temporal.PlainDate` everywhere; never `Date` | `npm run lint` — Biome `noRestrictedGlobals`, scoped to `src/**` | `Date` carries a zone and a time of day, and its arithmetic is not deterministic across platforms |
| ESM only; `"type": "module"`, no dual CJS build | `npm run typecheck`, `npm run check:publish` | [decisions/2026-08-11-build-tooling.md](decisions/2026-08-11-build-tooling.md) |
| Node 26+; the package checks for `Temporal` at import time | `engines` + the runtime guard in `src/computation/conversion.ts` | npm treats `engines` as advisory, so the guard covers the case the declaration cannot |
| Zero runtime dependencies | `npm run check:conventions` | The package's headline claim, and it runs through the lockfile as well as the runtime |
| No bundler; `tsc` alone emits `dist/` | `npm run check:publish`, `npm run test:pack` | The `./observances` subpath needs `dist/` to mirror `src/` |
| `npm pack` and `npm publish` build first, through `prepack` | `npm run test:pack` | Without it a bare publish ships whatever sits in `dist/`, stale or absent. `test:pack` deletes `dist/` and does not build, so the tarball has a build only if `prepack` made one |
| A shipped document links a repo-only file by absolute URL, and a shipped file relatively | `npm run test:pack` | A relative link to a repo-only file dies in `node_modules`; an absolute link to a shipped one works, so nothing fails, but it sends a reader to `main` instead of the copy beside it. The second was live in the README and `why-trust-these-dates.md` until the polyfill probe found it on 2026-09-23. A `files` entry matches exactly for a file and as a prefix for a directory |
| Never install Temporal typings — no `temporal-spec`, no `temporal-polyfill` | **review** | TypeScript 7 ships `lib.esnext.temporal.d.ts`; the zero-dependency claim runs through the published `.d.ts` |
| Generation-time packages resolve from the caller's working directory, never from `devDependencies` | **review** | `scripts/verify-name-sources.mjs` and `scripts/fetch-eszthoff-fixtures.mjs` both do this |

## Arithmetic and correctness

| Rule | Enforced by | Why |
|---|---|---|
| Integer arithmetic only; every division outside `src/computation/arithmetic.ts` carries an `exact:` comment saying why it cannot lose precision | `npm run check:conventions` | A float here is not a crash — it is a date that is right on one platform and wrong on another |
| Pure functions, judged by what a **caller** can observe | **review** | Memoising is therefore allowed, and is already done three times |
| No two functions in `src/` share a body | `npm run check:conventions` (Rule 14) | Catches copy-paste. Measured 2026-09-23 over 172 functions in 36 files — **before** the boundary work later the same day, which left 171 in 37; re-measure rather than reading the date. Exactly two pairs, zero false positives — `assertSafeYear` stood character-identical in `months.ts` and `computation/conversion.ts`, and `describe` in `traditions/validate.ts` and `observances/index.ts`. The quieter cost is not the repeated code but the **docblocks**: the two `assertSafeYear` copies explained different halves of the reasoning, so which half a reader got depended on which file they opened. Bodies under 40 characters are exempt — `return a % b;` may legitimately recur, and reporting it would train people to ignore the rule |
| A function that duplicates another's **job** but not its body | **review** | Rule 14 cannot see this, and it is the commoner case. `phaseStart` in `navigation.ts` and `isoOf` in `astrology/index.ts` both turn `PlainDate \| TibetanDate` into a `PlainDate`, with different bodies and different arity, so no predicate groups them — and they had already drifted, each shipping a message that misdescribes its own function. Both were written when `./astrology` landed on 2026-09-12, because the existing helper was **private** to another module and there was nowhere to look. So the guard is structural: boundary and guard code has one named home, and when a new subsystem lands, say which guards it wrote and whether one already existed |
| `instanceof Temporal` appears only in `src/temporal-kind.ts` | `npm run check:conventions` (Rule 15) | `instanceof` tests **identity** — whether the value came from this realm's `Temporal` — where this package needs **kind**. A `PlainDate` from a second implementation (a bundled polyfill, two non-deduplicated copies in `node_modules`, an iframe, a polyfill installed after import) fails every one. Five such checks had accumulated across three files by 2026-09-23 with nothing watching: **17 exports** read a foreign Western date as a Tibetan one and answered — `tibetanToIso` returned 1897-09-05 for ISO 2024-07-09 — and **10** refused a genuine Western date, including one case where the package refused a date it had produced itself. Use `temporalKindOf`, which reads `Symbol.toStringTag`. Comment lines are exempt, so the docblock explaining the rule may name the idiom. The rule is checkable **because the home is one named file**: one saying "outside the guards" would need the checker to know which functions count as guards. **Its reach is the idiom, not the concept**, and it matches `instanceof` against `Temporal` or against any of the three constructor names — so the qualified, aliased and destructured forms are caught, the last (`const { PlainDate } = Temporal`) being the likeliest accident. A single-identifier alias and a `getPrototypeOf` comparison still pass; both need binding resolution and neither is written by accident. A ratchet against the accident; not a proof of absence. See [decisions/2026-09-23-brand-not-identity.md](decisions/2026-09-23-brand-not-identity.md) |
| A cache keys on the config object, not only the year | **review** | A config-blind cache serves one tradition's answers for another, and would pass nearly every test |
| A cache never hands out shared mutable state | **review** | One consumer's `sort()` otherwise corrupts the next consumer's |

`PHUGPA` and `PHUGPA_HENNING` diverge at month level in only four years between 1500 and 2500, which is why a config-blind cache passes the suite.

## API surface and errors

| Rule | Enforced by | Why |
|---|---|---|
| Only the barrel in `src/index.ts` makes a name public | `test/public-api.test.ts` pins the list and each name's kind — **runtime exports only** | Exporting from a module under `src/` does not publish it — that is how `describeMonth` and `asPlainDate` are shared without being API |
| The **type lists** in `README.md` match what the barrels export | `npm run check:conventions` | Removing an exported type breaks no test — `test/public-api.test.ts` reads `Object.keys(api)` and types are erased, so a stale type list shipped once this way. The rule reads **all three** barrels and the three README lists, assigns each list to the entry point whose README section it sits in, compares them as sets, and is proved by mutation with an unmutated control. It was a two-element array and a single boundary string until 2026-09-12, which could not express three sections — and failed silently, the unextended rule passing while checking nothing about the new barrel |
| The **API tables** in `README.md` list every runtime export of the barrel whose section they sit in, and its **error table** lists every `TibetanCalendarErrorCode` | `npm run check:conventions` (Rule 16) | `test/public-api.test.ts` pins the surface against itself, never against what the README promises, so the Tradition configs table listed two of four shipped configs and the error table omitted `TCT_ATTRIBUTE_NOT_SOURCED` until the polyfill probe found both on 2026-09-23. The rule reuses Rule 13's section ranges, reads a row only when its first cell is one backticked identifier, and compares as sets in both directions. `SkippedDayError` has no row, being a class; it counts as documented while the Errors subsection still describes it by name. Proved by mutation — R16 for the API tables, X11 for the error table — with an unmutated control |
| Prose **describing a config's contents** is not checked either | **review** | Same class as the row below, different subject. `docs/roadmap.md` said `GELUG` ships "eleven shipped rules (four fixed-date duchens, six monthly-cycle rules)" from 2026-08-28 to 2026-09-04 — the arithmetic beside it always said ten, and `README.md` said ten correctly throughout. The file now holds 19 rules, and a count is derived from the config, not the file: `EXAMPLE_OBSERVANCES.rules.length`, or `grep -c '^\s*id: "'` over the file, which gives 20, the 19 rules and the config's own (the three levels are written inline and are not counted by that grep). Nothing counts a config's rules against the prose describing them; it was caught by an architecture review of an unrelated plan |
| Prose **describing a type's fields** is not checked | **review** | Rule 13 closes the list, not the sentences around it. `README.md` described `rabjungFor`'s `name` as carrying Sanskrit for hours after it stopped doing so, and no predicate available here would have seen it. `docs/architecture.md` carries 29 shapes as `interface` blocks and `docs/guide.md` names 4 types in prose, with no list to compare — sweep those by hand. **Re-count rather than trusting that 29**: it read 7 here until 2026-08-27 while CLAUDE.md said 10, both were wrong, it moved to 13 and then 20 on 2026-09-12 as `TraditionMonthNaming` and the seven astrology shapes landed, to 21 on 2026-09-13 when that type split in two, and to 24 and then 25 on 2026-09-14 with `monthNamesFor`'s result types and `LunarMansion`, and to 26 with `YogaAuspiciousness`, and back to 25 on 2026-09-24 when `AstrologyQueryOptions` was removed, and to 29 on 2026-11-14 with `Observance` added and the observance shapes made complete |
| A shape in `docs/architecture.md` is **complete** — every field, not a selection | **review** | The rule that keeps failing silently. `TibetanDate` drifted to 10 of 15; the 2026-08-27 sweep found `TibetanYearName` at **3 of 6** — the three `*Name` fields arrived on 2026-08-16 and the shape was never touched — and `TibetanMonthFields` missing its `calendarId` phantom. Adding a field to an exported type includes updating its shape here |
| A bare `{ year, month, day }` is refused wherever a parameter spans **two calendars** | `test/navigation.test.ts` — a runtime case **and** a `@ts-expect-error` | The object is a genuine value of both `TibetanDateFields` and Temporal's own fields shape, so it names neither. `nextFullMoon` accepted it for one day in 2026-08 and returned **1899-02-25** for a date meant as 2026. Does not generalise: `addDays`, `daysBetween` and `addMonthsToDate` span one calendar and keep taking loose fields |
| A compile-time contract is guarded with `@ts-expect-error`, checked by `npm run typecheck` | `npm run typecheck` — `tsconfig.json` includes `test/**/*.ts` | `tsc` errors on an **unused** directive, so the guard fails the moment the thing it forbids starts compiling again. It is the repo's only compile-time tripwire and the first landed 2026-08-27; prove a new one by running it against the code *before* the change, where it must report `TS2578`. Do not delete one as a stray directive |
| The `*For` accessors in `cycles.ts` wrapped the `*Of` lookups in `names.ts`, one character apart | **resolved 2026-08-25** | Writing the public name where the internal one belonged **compiled**, since both returned the same name type, and recursed infinitely rather than failing to typecheck. Judged not worth the churn on 2026-08-17, which held only while there were four instances. Three went when the element, gender and animal wrappers came off the surface; the last was fixed by renaming `weekdayNameOf` to `weekdayNameWithOffset` — named for what it does, since the offset is the whole Bhutan difference and its three siblings take none. Do not "tidy" that asymmetry back |
| The two conversion-naming families are **both correct**: the first word names either the **argument** (`aToB`) or the **return** (`aFromB`) | **review** | Examined 2026-08-26 as a suspected inconsistency and found not to be one. `isoToTibetan(isoDate)` and `tibetanToIso(fields)` lead with the argument; `julianDayFromIso(isoDate)`, `isoFromJulianDay(jd)`, `lunationFromMonth(month)` and `monthFromLunation(lunation)` lead with the return. All six pass. This is **Temporal's own split** — `PlainDate.from(…)` constructs the named type from something else, `.toPlainDate()` converts a subject to a target — and `isoToTibetan(isoDate)` is that method call flattened into a free function. Recorded so it is not "unified" later; the churn, deliberately not part of the decision, is 417 repo references on the `To` pair against 179 on the four `From` names |
| A **bare-noun function name** is permitted only where it mirrors a same-named field computing the same value | **review** | `tibetanWeekday` is the sole instance and its docblock states the principle. Do not expand the pattern: this package has **no namespace object**, so every export lands directly in a consumer's import scope, where `months`, `losar` or `yearName` would collide with their own variables. `hebcal` can afford `hdate.months` because the receiver scopes it; a bare ESM barrel cannot |
| No exported identifier names an institution; provenance goes in the docblock and the docs, never the name | **review** | `GELUG`, the observance config's export name until it was renamed, was FPMT's specific published convention, not "the Gelug way" — Kopan Monastery, also Gelug, prints the opposite `doubledDay` for the same date. The name overclaimed a universality the data contradicted. The export is now `EXAMPLE_OBSERVANCES`. See [decisions/2026-09-03-no-institution-names-in-exports.md](decisions/2026-09-03-no-institution-names-in-exports.md) |
| The shipped config's data fields claim no lineage either — `id` is `"example"` and `englishName` is `"Example practice calendar"` | `test/public-api.test.ts` asserts `id` explicitly | Whose conventions the example follows is stated in its docblock and in [observances.md](observances.md), where a citation fits. `id` is documented as a *stable identifier*, so a role such as `"default"` would have to migrate or lie once a second config ships; `"example"` names what the object is for. An FPMT id belongs on FPMT's own configuration, which lives in the test suite |
| A `TraditionConfig` is always named `tradition`, positional or as a bag key; a one-choice function takes it last and positionally; two or more choices go in one bag extending `TraditionOptions`, which holds only `tradition`; a new choice defaults to the old behaviour; a one-choice function gaining a choice converts to a bag | **review** | Points 1–4, 6 and 7 of [decisions/2026-09-24-how-a-tradition-is-passed.md](decisions/2026-09-24-how-a-tradition-is-passed.md). Replaced, on 2026-09-24, "a function with two axes of choice takes an options bag", which decided the shape and inherited the keys: `config` meant a `TraditionConfig` in one bag and an `ObservanceConfig` in another, and from JavaScript a positional tradition passed to a bag function was ignored. Nothing mechanical holds these; point 1 is the checkable one, and the first candidate for a `check:conventions` rule if it regresses. The older lessons still apply to every bag: **a bag is a new argument boundary and needs its own guard**, and read it with `=== undefined`, never `??` |
| An options bag refuses a key it does not have (point 5), inherited keys included; a `TraditionConfig` does not, an `ObservanceConfig` and an `ObservanceLayer` do | `npm test` (`test/errors.test.ts` on `assertQueryOptions`, and each bag's suite) | Every bag ignored unknown keys until 2026-09-24, so `{ tradtion: BHUTAN }` or the renamed `{ config: BHUTAN }` took the default silently. `assertQueryOptions` builds its message's shape from the allowed-key list, so the shape cannot name a stale key. A `TraditionConfig` keeps accepting extra keys: `{ ...PHUGPA, extra }` is supported. An `ObservanceConfig` refuses an unknown key on every object it contains — the config, a rule, a level, a `when` and a date — and `composeObservances` on its layer (`npm test`, `test/observances/index.test.ts` and `compose.test.ts`): a misspelt field is a setting that does nothing. It no longer takes a bag at all |
| A setting a rule's form does not use is refused, and an invalid value keeps its own message | `npm test` (`test/observances/index.test.ts`, *a per-rule setting the form cannot use*) | `monthly` does not read `leapMonth`, `western` reads none, and `period` reads only `leapMonth`; a valid value on a form that ignores it throws, so a setting never looks effective while doing nothing. The value is checked before its applicability, so `leapMonth: "sometimes"` on a `monthly` rule reports the bad value and not the inapplicability. `skippedDay: "omit"` on a `counted` rule is refused, set on the rule or inherited from the config, because an omitted anchor leaves the schedule undefined |
| A rule gives **one result per calendar day**, whatever its entries | `npm test` (`test/observances/index.test.ts`, *one result per rule per calendar day*) | A rule naming days 29 and 30 in a month whose 30th is skipped lands both on one day; the result keeps the exact landing, then a doubled half, then a shifted day. `getObservances`, `observancesOn` and `nextObservance` agree because they share the rule's own occurrence function |
| A type import can outlive its last type use, and `noUnusedLocals` will not say so | **review** | TypeScript counts a JSDoc `{@link}` as a use. So a symbol used in both a signature and a docblock link keeps its import alive after the signature goes, silently — which is exactly what happened to `TibetanElement` in `cycles.ts` on 2026-08-25, where three sibling imports were flagged as TS6196 and it was not. Nothing catches this: `tsc`, Biome and `check:conventions` all pass either way. **When removing a public function, grep its parameter types by hand** rather than trusting the compiler's sweep. The link itself needs no import — `{@link TibetanDate.year}` resolves in that same file with `TibetanDate` unimported, which is the pattern to follow |
| What earns a public slot is decided by a rule with a scope | [decisions/2026-08-12-public-surface.md](decisions/2026-08-12-public-surface.md) — **review** | The **wrong-or-impossible** test governs computation internals and contested conventions; a thin composition over public functions is judged differently. The record was misapplied once and cost the surface four functions |
| A **tradition config** is exported only once its dates are validated day by day against an external calendar | `npm run check:conventions` (every exported config must be **imported** by a suite in `test/validation/`), plus [decisions/2026-08-16-exported-means-validated.md](decisions/2026-08-16-exported-means-validated.md) | A config is a factual claim about a calendar, not an API-design question. Tsurphu and the Mongolian version are fully expressible with validated leap months and stay unexported, because nothing checks a *date* |
| Imported, not mentioned — a comment or a `describe` title does not evidence a config | `npm run check:conventions` (namespace and default imports are deliberately not matched, and would fail loudly rather than pass silently) | The rule grepped concatenated suite text until 2026-08-17, so deleting a suite's assertions while leaving the prose behind kept it green |
| Errors carry codes; throw through `rangeError`, `codedError` or `assertInternal` in `src/errors.ts` | `npm run check:conventions` | The code is the part consumers branch on, and a bare construction silently omits it |
| `SkippedDayError` is the only error class and stays the only one | **review** | [decisions/2026-08-12-error-codes-not-classes.md](decisions/2026-08-12-error-codes-not-classes.md) |
| `TCT_FIELD_OUT_OF_RANGE` for a wrong **number**; `TCT_INVALID_ARGUMENT` for the wrong **kind of thing** | **review** | Only the first is on `tibetanDateExists`'s allowlist, which is what makes a caller's type confusion throw rather than be reported as a date that does not exist — [decisions/2026-08-15-argument-errors-split.md](decisions/2026-08-15-argument-errors-split.md) |
| `tibetanDateExists` swallows by **allowlist**, never denylist | **review** | As a denylist, one bare `RangeError` in `scaleTo` made it report that Losar 2026 does not exist |
| A guard renders a value it has not yet type-checked through `describe`, never a bare `${}`; `describe`, `isPlainObject` and `thrownDetail` never throw | `test/hostile-inputs.test.ts`, which calls every runtime export of the three barrels with seven values a template cannot render and five single-trap Proxies, and fails on any uncoded throw — the **outcome**, not the idiom | A message is built after the decision to throw, so a renderer that throws turns a coded error into an uncoded one: fourteen sites did until 2026-09-24, and `10n` and `"10"` both printed as `10`. **Probe with one throwing trap at a time**: the table's first Proxy was a revoked one, which throws at the first trap any code reaches — a read already guarded — and so hid a message helper and two unguarded reads behind it until an independent review |
| An error the **caller's own code** throws while a config or a date's fields is read may propagate uncoded; a guard that already wraps such a read uses `TCT_INVALID_ARGUMENT`, never `TCT_FIELD_OUT_OF_RANGE` | **review** — the README states the boundary beside its code table | Decided 2026-09-24 over converting, because a config is read again after validation and only a validator returning a frozen copy would close it. The range code is on `tibetanDateExists`'s allowlist, so wrapping a throwing getter with it would answer "that date does not exist". See [decisions/2026-08-12-error-codes-not-classes.md](decisions/2026-08-12-error-codes-not-classes.md) |
| Codes are contract; message text is not | `test/public-api.test.ts` asserts the codes | Assert on the code in tests, and never tell a consumer to match wording |
| A message names the function the caller called, and for a two-argument function which argument | `test/error-subjects.test.ts`, which calls every Tibetan month- and date-tier export with four bad inputs and pins each message's opening as an anchored pattern | Seven exports borrowed another's guard and reported under its name until 2026-09-24 — `monthNamesFor` saying `daysInMonth(`, `addDays` saying `tibetanToIso(`. The text is not contract, so this pins which function is *named*, not the wording; and never with `toContain`, which let " to find" satisfy a check for the argument `to` |
| Every `TCT_` code named in `src/` — in a `@throws` or a `codedError` call — is a real union member | `npm run check:conventions` | Both are string literals, so a typo is not a type error: it sends a consumer branching on a code that is never thrown |
| `noUncheckedIndexedAccess` is discharged with `assertInternal`, not a cast | `npm run check:conventions` (the cast route needs no `new Error`, so this is partly **review**) | A cast lets a bad index return `undefined` wearing the element type |

## Configuration and extension

| Rule | Enforced by | Why |
|---|---|---|
| Tradition constants are injected via `TraditionConfig`, never hardcoded | `test/tradition-config.test.ts`, `test/validation/cross-version-leap.test.ts` | Tested rather than asserted: Bhutan was added on 2026-08-16 with two new config fields and no change to any formula. Tsurphu and the Mongolian version must stay equally addable |
| The **rules** are injected too, not only the numbers | `test/computation/calendar-leap-index-threshold.test.ts` | This promise was false until 2026-08-16: every constant was injected while the leap-month rule was hardcoded to Phugpa's 48/49 |
| A bound proved from a config's numbers is **derived** from that config | **review** | The `±3` search window was proved from Phugpa's tables and written as a literal, then broke 8% of days for a wider table. It is now `ScaledTradition.searchHalfWidth` |
| Every consumer config gets a validator, memoised per object | `src/traditions/validate.ts`, `src/observances/types.ts` — **review** for new config types | `TraditionConfig` went unchecked for three phases because the failure looked like a language error |
| A field the type declares **required** is rejected when absent, not merely when wrong | **review** | `undefined` is the likelier input, and it silently inherited whichever branch came last |
| An internal caller skipping a guard gets a separate name, like `isoFromJulianDayUnchecked` | **review** | The boundary is the whole exported surface; leaving the export bare removes it |
| The shipped configs are deeply frozen | `test/public-api.test.ts`, `test/observances/index.test.ts` | Scaling and validation are both memoised on the config object, so a post-freeze mutation yields neither the old constants nor the new ones but a stale mix |

## Tests and fixtures

| Rule | Enforced by | Why |
|---|---|---|
| Fixtures are generated by a committed script, not transcribed | `npm run check:conventions` | Hand-copying 120 dates is how a silent one-day error reaches the primary correctness gate |
| `test/fixtures/fpmt-holy-days.ts`, `test/fixtures/rgob.ts` and `test/fixtures/henning-six-seasons.ts` are the only hand-curated fixtures | `npm run check:conventions` (allowlisted by name; `npm run test:conventions` row X8 for the third) | Each earns it the same narrow way — the source has **no usable markup**, so a generator could only wrap a lossy reading. FPMT publishes in prose; the Royal Government of Bhutan publishes a scanned PDF with no text layer; Henning's six-season list is a scanned book whose OCR shifts columns against rows (the pairing was read by eye; the page per row was not). "Parsing it is inconvenient" is not the test |
| A fixture declaring only types is exempt from provenance, and is checked **before** the generator lookup | `npm run check:conventions` | `crosscheck-row.ts` has nothing to transcribe. Checked first because the generators emit an import naming it, so it would otherwise pass by accident — a provenance rule passing for the wrong reason is worse than one that fails |
| Every file in `test/fixtures/` imports only from `test/fixtures/` | **review** | That closure is what lets "fixtures do not depend on the engine" be true by inspection. `test/support/` is not engine-free — `versions.ts` imports from `src/` — so a shared fixture type belongs in `fixtures/`, not `support/` |
| Test files must not export; a shared helper goes in `test/support/` | `npm run lint` — Biome `noExportsInTest` | An import across test files makes vitest re-run the imported file; the suite once reported 669 tests where 641 existed |
| An unused import fails the build | `npm run lint` — Biome `noUnusedImports`, **escalated to `error`** | It is recommended but defaults to `warn`, and `biome check` passes on warnings. Escalated so Rule 10 cannot be satisfied by an import left behind after its assertions were deleted |
| A validation suite is named for the fixture, or fixture prefix, it validates, and lives in `test/validation/` | `npm run check:conventions` | Parity is what lets a reader find the test for a fixture without opening anything. It drifted: a suite called `bhutan-fixture.test.ts` sat under a third test directory of its own invention. The one allowlisted exception, `observances.test.ts`, was retired on 2026-09-12 when the suite was split into the half that validates against FPMT and the half whose subject is the engine |
| A directory under `test/` earns its place by mirroring one under `src/` | `npm run check:conventions` | The sanctioned set was hardcoded as four names, of which only `computation` was a module-suite mirror. It went stale as soon as `src/` grew a second subsystem, leaving `src/observances/` with nowhere to put a module suite |
| Taking a fixture as *input* does not make a test a validation suite | `npm run check:conventions` — the rule is deliberately blind outside `test/validation/` | `test/computation/conversion.test.ts` imports `losar` and is named for its module, correctly. This is the half a later sweep gets wrong |
| A suite in `test/<name>/` is named for a module in `src/<name>/`, optionally narrowed as `<module>-<concept>` | `npm run check:conventions` (longest-prefix, **not** first `-` segment — that rejects `mean-astronomy.test.ts`, which is already correct) | Two suites were named for a *concept* instead. A suite spanning several modules is not a module suite: `leap-month-position.test.ts` touches four and belongs at `test/` root |
| A generated document may not hardcode a count the generator computes | `npm run check:conventions` — a literal English number-word in the same **sentence** as a `${}` interpolation, in the markdown template a generator emits | `docs/names/rabjung.md` read "Four values are marked, at positions 6, 15, 31, 37, 60" for three commits: the list is interpolated, the word is a literal, and there were five positions and nine marked cells. Digits are not flagged — `${n} of the 60` is legitimate — and the sentence boundary is load-bearing, or the rule fires on a pronoun two sentences away |
| The checker's own predicates are proved before any rule runs | `npm run check:conventions` — `selfTest()`, on every invocation, reporting "the checker itself is broken" rather than a violation | Eleven rules and nothing proved any fired. | README examples stay true | `test/readme.test.ts` | Change an example, update the test in the same commit |
| Guide examples stay true | `test/guide.test.ts` | `docs/guide.md` ships to npm, so its examples are contract exactly as the README's are. A suite named for one document while guarding another is one nobody thinks to update |

### Sanskrit and Tibetan terminology

These govern the **prose** in `docs/` and `README.md`. All **review**.

They do **not** govern a tabulated or shipped data column. Those follow a published standard —
THL Simplified for phonetics — because house style cannot be verified against anything, and a
column nothing can check is a column nothing can defend. `docs/names/rabjung.md`'s phonetic column
was house style until 2026-08-21 and is now THL, generated rather than written.

- Sanskrit terms carry full IAST diacritics plus Devanāgarī, with no comma between them.
- Tibetan terms are formatted `English term (IAST Devanāgarī; Tibetan script pronunciation)`.
- Phonetic renderings are italicised, lowercase except for proper nouns, and reflect spoken Lhasa dialect rather than Wylie — devoicing, tonal register, lost prefixes and superscripts, and the sandhi rules including final ས → n before a vowel-initial syllable.
- Omit the final tsheg on isolated terms, and prefer canonical Tibetan terms.

The Wylie and Tibetan-script columns of the shipped vocabulary are **not** governed by this — they are generated and verified by `npm run verify:names`.

## Required checks

CI runs these ten, in this order, on Ubuntu, Windows and macOS.
All ten run locally with the same commands.

```sh
npm run lint
npm run lint:md
npm run check:links
npm run check:conventions
npm run test:conventions
npm run typecheck
npm run build
npm test
npm run check:publish
npm run test:pack
```

The last two are the only checks that see the **published** package.
Every test imports from `src/`, so a broken `exports` map, a file missing from `files`, or a `dist/` layout that does not match `exports` is invisible to the suite and fails only for a consumer, after publishing.

`attw` runs under `--profile esm-only`. Its `node10` and `node16-cjs` rows are the deliberate design, not defects — there is no `main` field and no CJS build.

### Seven release-time checks, deliberately outside CI

| Command | Why it cannot gate a push |

**A performance number may be quoted only with its harness.** The project refuses unsourced numbers from its calendar sources, and the rule applies to its own: machine, OS, Node version and date, as `bench/RESULTS.md` records them. `CLAUDE.md`'s `monthsFor` cache figures were asserted for months before anything measured them.

## Adding a rule

If you find a convention worth holding, add it here **with its enforcement column filled in**, even if the answer is **review**.
A rule that is not in this table is not a rule anybody can be held to, and a **review** row is a visible backlog item rather than a silent gap.

If the rule is mechanically checkable, it belongs in `scripts/check-conventions.mjs`.
Write the failing case first and confirm the check reports it — a guard that has never failed proves nothing.
Write it as a function, add it to `RULES`, and raise the rule count the self-test expects; a rule that is written but not registered never runs.
Then add its mutant to `test/check-conventions.mutations.ts` and run `npm run test:conventions` — the suite refuses a registered rule with no mutant.
That script also verifies this document against reality: every `npm run` command and every path it names must exist, so the map cannot quietly drift the way a prose restatement would.
